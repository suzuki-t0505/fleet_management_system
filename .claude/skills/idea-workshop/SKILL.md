# アイディアワークショップスキル

壁打ち → 全批判 → 最終統合の3フェーズでアイディアを徹底的に精練する。

---

## フェーズ0: 事前調査

アイディアセッションを開始する前に、以下の調査を必ず実施する。

### 0-1. CLAUDE.md を読む

`CLAUDE.md` を読み、プロジェクトの技術スタック・開発方針・ルールを把握する。

### 0-2. 永続ドキュメントを読む

`docs/` 配下の以下ドキュメントを読み、プロジェクト全体の設計・仕様を把握する:

- `docs/product-requirements.md`（存在する場合）
- `docs/functional-design.md`（存在する場合）
- `docs/architecture.md`（存在する場合）
- `docs/glossary.md`（存在する場合）

### 0-3. 既存の類似実装を Grep で検索

トピックに関連するキーワードでコードベースを検索し、既存の類似実装・関連モジュールを把握する。

```bash
grep -r "{関連キーワード}" lib/ --include="*.ex" -l
```

### 0-4. 既存パターンを理解してからセッション開始

上記の調査結果を踏まえ、プロジェクトの文脈・制約・既存実装を理解した上でフェーズ1に進む。

---

## フェーズ1: 壁打ちと要点整理

### 1-1. トピック確認

引数でトピックが指定されていればそれを使う。なければユーザーに確認する。
トピックからファイル名スラッグを決める（英数字・ハイフンのみ。日本語はローマ字化）。
出力ファイルパスを決定する:

- 壁打ち: `docs/ideas/{slug}-brainstorm.md`
- 批判:   `docs/ideas/{slug}-criticism.md`
- 最終:   `docs/ideas/{slug}-final.md`

### 1-2. 壁打ちセッション（対話形式）

以下の7つの質問を**一問一答で順番に**ユーザーに投げかける。
前の回答を踏まえて次の質問のトーンや深さを調整する。

1. **課題**: このアイディアで解決しようとしている課題は何ですか？今その課題はどう解決されていますか？
2. **ターゲット**: 誰のためのアイディアですか？どんな人・組織が使いますか？
3. **コア**: アイディアの核心はどんな仕組みですか？既存の代替手段と比べて何が違いますか？
4. **実現性**: 技術的・リソース的に何が一番難しいですか？必要なものは何ですか？
5. **価値**: うまくいった場合、何がどう変わりますか？成功をどう測りますか？
6. **リスク**: うまくいかない場合、主な理由は何だと思いますか？
7. **最初の一手**: 最小限で試せる検証ステップは何ですか？

### 1-3. 壁打ちレポートの生成

7問の回答を元に以下フォーマットで壁打ちレポートを生成し `docs/ideas/{slug}-brainstorm.md` に保存する。

```markdown
# アイディア壁打ちレポート: {トピック}

作成日: {YYYY-MM-DD}

---

## 概要

{アイディアの1〜3文要約}

---

## 解決する課題

{課題の説明と現状の解決策}

## ターゲット

{対象ユーザー・組織の具体像}

## ソリューションのコア

{核心的な仕組みと差別化ポイント}

## 実現に必要なもの

{技術・リソース・スキル・外部依存等}

## 期待される価値と成功指標

{効果・成功の定義・測定方法}

## 想定リスク

{主なリスクと懸念点}

## 最初のアクション

{最小限の検証ステップ}

---

## 壁打ちメモ（生のアイディア・断片）

{整理前の気付き・メモ・派生アイディア}
```

保存後、ユーザーに以下を伝える:

> 「壁打ちレポートを `docs/ideas/{slug}-brainstorm.md` に作成しました。内容を確認してください。
> 承認いただけたらフェーズ2（批判レポート生成）に進みます。」

---

## フェーズ2: 批判レポートの生成

ユーザーの承認後、以下のAgentを起動して批判レポートを生成する。

```
Agent(
  description: "アイディア批判レポート生成",
  subagent_type: "idea-critic",
  prompt: "{slug}-brainstorm.md のパスを渡す"
)
```

具体的には `idea-critic` エージェントに以下を伝える:

- 壁打ちファイルパス: `docs/ideas/{slug}-brainstorm.md`
- 出力ファイルパス: `docs/ideas/{slug}-criticism.md`
- トピック名: {トピック}

批判レポート生成後、ユーザーに以下を伝える:

> 「批判レポートを `docs/ideas/{slug}-criticism.md` に作成しました。内容を確認してください。
> 承認いただけたらフェーズ3（最終アイディアレポート生成）に進みます。」

---

## フェーズ3: 最終アイディアレポートの生成

ユーザーの承認後、以下のAgentを起動して最終レポートを生成する。

```
Agent(
  description: "最終アイディアレポート生成",
  subagent_type: "idea-finalizer",
  prompt: "brainstorm と criticism の両パスを渡す"
)
```

具体的には `idea-finalizer` エージェントに以下を伝える:

- 壁打ちファイルパス: `docs/ideas/{slug}-brainstorm.md`
- 批判ファイルパス:   `docs/ideas/{slug}-criticism.md`
- 出力ファイルパス:   `docs/ideas/{slug}-final.md`
- トピック名: {トピック}

最終レポート生成後、ユーザーに3つのファイルパスを伝えてワークショップ完了を告げる:

> 「アイディアワークショップが完了しました。
>
> - 壁打ち: `docs/ideas/{slug}-brainstorm.md`
> - 批判:   `docs/ideas/{slug}-criticism.md`
> - 最終:   `docs/ideas/{slug}-final.md`」

---

## 重要なルール

- 各フェーズ後に必ずユーザーの承認を得てから次に進む
- 壁打ちは一問一答。7問を一気に並べない
- スラッグは英数字とハイフンのみ（例: `ai-matching-tool`, `unifield-reporting`）
- `docs/ideas/` ディレクトリが存在しない場合は `mkdir -p docs/ideas` で作成する
