# アイディア実装スキル

`docs/ideas/` の最終アイディアレポートをもとに、`.steering/` ドキュメントを作成し、実装・テスト・永続ドキュメント更新までの全フローを実行する。

---

## フェーズ1: アイディア選択

### 1-1. 未実装のアイディアを列挙

```bash
ls docs/ideas/*-final.md
```

各 `*-final.md` ファイルを開き、冒頭に `## ステータス: 完了` セクションが**ない**ものを「未実装」として扱う。

### 1-2. 複数ある場合

ユーザーに一覧を提示し、1つだけ選んでもらう:

> 「以下の未実装アイディアがあります。今回実装するものを1つ選んでください:
> 1. {トピック名} — `docs/ideas/{slug}-final.md`
> ...」

### 1-3. 1つだけの場合

そのアイディアで確認する:

> 「`docs/ideas/{slug}-final.md` を実装します。よろしいですか？」

---

## フェーズ2: ステアリングドキュメント作成

ユーザーの承認後、`steering-doc-creator` エージェントを起動する。

```
Agent(
  description: "ステアリングドキュメント作成",
  subagent_type: "steering-doc-creator",
  prompt: """
  以下の最終アイディアレポートをもとに、ステアリングドキュメントを作成してください。

  - アイディアファイル: docs/ideas/{slug}-final.md
  - ステアリングディレクトリ: .steering/{YYYYMMDD}-{slug}/
    - requirements.html: 今回の作業要求（最終アイディアから抽出）
    - design.html: 実装アプローチ（既存コードパターンを調査して設計）
    - tasklist.html: チェックボックス形式のタスクリスト

  作業日: {今日の日付 YYYYMMDD}
  スラッグ: {slug}
  """
)
```

エージェント完了後、3ファイルをユーザーに確認してもらう:

> 「ステアリングドキュメントを作成しました。内容を確認してください。
> - `.steering/{date-slug}/requirements.html`
> - `.steering/{date-slug}/design.html`
> - `.steering/{date-slug}/tasklist.html`
>
> 承認いただけたら実装フェーズに進みます。」

---

## フェーズ3: 実装

ユーザーの承認後、以下の手順で実装を進める。

### 3-1. tasklist.html を読み込む

`.steering/{date-slug}/tasklist.html` を読み、タスク一覧を把握する。

### 3-2. タスクを順番に実行する

各タスクを1つずつ実行し、完了したら `tasklist.html` の該当タスクの `<input type="checkbox">` に `checked` 属性を追加する。

**実装のルール:**
- CLAUDE.md の「実装前の確認」セクションに従う
- 既存の類似実装パターンを必ず grep で確認してから実装する
- 1ファイルずつ作成・編集し、複数の独立した変更は並列実行してよい
- 大きな変更の前はユーザーに方針を確認する

### 3-3. 実装中の報告

各タスク完了後に簡潔に報告する:
> 「[タスク名] 完了。次: [次のタスク名]」

---

## フェーズ4: テスト

実装完了後、以下のコマンドでチェックを実行する:

```bash
make check
```

失敗した場合:
- エラーの原因を特定して修正する
- 修正後に再実行する
- `make check` が通るまで繰り返す

---

## フェーズ5: 永続ドキュメントの更新確認

`persistent-doc-updater` エージェントを起動し、実装内容が `docs/` 配下の永続ドキュメントに影響するかを判定・更新させる。

```
Agent(
  description: "永続ドキュメント更新確認",
  subagent_type: "persistent-doc-updater",
  prompt: """
  以下のステアリングドキュメントに記録された実装内容をもとに、
  docs/ 配下の永続ドキュメントへの影響を判定し、必要なものを更新してください。

  ステアリングディレクトリ: .steering/{date-slug}/
  （requirements.html・design.html・tasklist.html の3ファイルを読んでください）
  """
)
```

エージェントの結果をそのままユーザーに伝える。

---

## フェーズ6: アイディアを完了マーク

`docs/ideas/{slug}-final.md` の冒頭（タイトルの直後）に以下のセクションを挿入する:

```markdown
## ステータス: 完了

- 実装完了日: {YYYY-MM-DD}
- ステアリング: `.steering/{date-slug}/`
- 関連PR/コミット: {コミットハッシュまたはPR番号（あれば）}

---
```

挿入後、ユーザーに完了を報告する:

> 「実装が完了しました。
>
> - 実装内容: {一言サマリー}
> - ステアリング: `.steering/{date-slug}/`
> - 永続ドキュメント更新: {更新したファイル一覧、なければ「なし」}
> - アイディアを完了マーク: `docs/ideas/{slug}-final.md`」

---

## 重要なルール

- **アイディアは1つだけ**: 複数の未実装アイディアがあっても、1回のスキル実行で実装するのは1つのみ
- **承認制**: フェーズ2終了後（ステアリングドキュメント確認）とフェーズ3開始前に必ずユーザー承認を取る
- **既存パターン優先**: 実装は既存コードのパターンを踏襲する
- **テストが通ること**: `make check` が通らなければ完了としない
- **完了マークは最後**: テストが通り、永続ドキュメント更新まで終わってから完了マークを付ける
