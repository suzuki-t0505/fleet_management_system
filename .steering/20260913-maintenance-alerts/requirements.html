.steering / 20260913-maintenance-alerts

要求内容：点検整備・期限アラート

対象機能: F-5 点検・整備記録と期限アラート（product-requirements.md / functional-design.md 4.3・6.4・7）

1. 背景

車両台帳（F-2）に車検満了日・自賠責/任意保険満了日・次回点検予定日を保持しているが、 期限を見に行かないと気付けない状態にある。車検切れ運行は行政処分（使用停止）に直結するため、 プロダクト要求では「期限切れ 0件」を KPI にしている。

あわせて、点検整備の実施記録が Excel・紙に散在しており、整備費の集計（F-7）と法定点検の実施証跡が取れない。 記録の登録と、記録から次回期限を自動更新する導線をここで作る。

2. 目的

  • 期限切れを「起きてから気付く」状態から「60日前から通知が届く」状態にする
  • 点検整備を記録すると、車両台帳の次回期限が自動で更新される状態にする（二重入力をなくす）
  • 運行管理者が、自拠点の迫っている期限を1画面で残日数順に確認できるようにする
  • 整備費の集計（F-7）に必要なデータを蓄積する

3. 対象範囲

#優先度要求
R-1P0 点検整備記録の登録・編集。車両・実施日・区分・オドメーター・実施業者を必須、費用・作業内容・次回予定日を任意とする
R-2P0 記録から車両の期限を更新（V-20・V-21）。車検は inspection_expires_on、3ヶ月/12ヶ月点検は next_periodic_3m_on / next_periodic_12m_on を、記録の保存と同一トランザクションで更新する
R-3P0 入力検証（V-20〜V-23）。実施日の未来日はエラー、オドメーターの逆転は警告（保存可）
R-4P0 点検整備記録の一覧・詳細（/management/maintenances）。期間・車両・区分・拠点で絞り込む
R-5P0 期限アラート一覧（/management/alerts）。6種の期限を横断し、残日数の昇順で表示する。残日数に応じて配色する
R-6P0 期限の定時判定。毎日 JST 07:00 に走査し、残り 60 / 30 / 7 / 0 日と超過を抽出する。廃車・退職者は対象外
R-7P0 メール通知。対象拠点の運行管理者全員と全管理者に送る。送信結果を alert_notifications に記録し、同一段階を二重送信しない
R-8P0 超過中の再通知。期限超過は毎日ではなく7日ごとに通知する
R-9P0 失敗時の扱い。送信失敗は failed として記録し、翌日の実行で再送対象に含める。ジョブ自体の異常終了は全管理者にエラー通知する
R-10P0 ダッシュボード連携。運行管理者・管理者に「期限超過」「30日以内」の件数を表示し、アラート一覧へ遷移できるようにする
R-11P1 車両詳細からの導線。車両詳細に点検整備履歴を表示し、その車両を選んだ状態で登録画面へ遷移できるようにする

4. 対象外（今回やらないこと）

項目理由
整備記録への添付ファイル（V-5相当）添付は attachments 集約として別作業で一括実装する（車両・事故と共通化するため）
整備費の集計レポートF-7 の範囲。本作業ではデータの蓄積までを行う
点検整備記録の削除台帳と同じく物理削除は行わない方針。誤登録は編集で直す
期限アラートの画面内通知（ベル）・Slack 連携MVP はメールと一覧画面に限定する
リース満了日のアラートfunctional-design 7.1 の監視対象6種に含まれない（一覧の表示のみ既存）

5. 受け入れ条件

  • 車検の記録を登録すると、車両の車検満了日が入力した次回満了日に更新されている
  • 車検・3ヶ月点検・12ヶ月点検で次回予定日を空にすると保存できない
  • 実施日に未来日を入れると保存できない
  • 登録時のオドメーターが車両の最終オドメーターを下回ると警告が出るが、保存はできる
  • 運行管理者は他拠点の車両を選べず、他拠点の記録・アラートが一覧に出ない
  • 期限アラート一覧が残日数の昇順で並び、超過=赤 / 7日以内=橙 / 30日以内=黄で表示される
  • 定時ジョブを2回実行しても、同じ段階のメールが2通送られない
  • 超過中の対象は、超過1日目には送られず、7日ごとに送られる
  • 廃車の車両・退職した運転者は、一覧にも通知にも現れない
  • make check（compile / format / credo / test）がすべて通る
前提：車両台帳（F-2）・運転者台帳（F-3）・運行日報（F-4）は実装済み。 Oban は導入済みで alerts / mailers キューが設定済み、crontab は空の状態にある。
