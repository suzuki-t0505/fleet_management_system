.steering / 20260913-organization-management

要求内容：組織・拠点・ユーザー管理

対象機能: F-1 組織・拠点・ユーザー管理（product-requirements.md F-1 / functional-design.md 2・3.3・4.3）

1. 背景

拠点とアカウントは全機能の前提（拠点スコープ・ロール・監査ログの操作者）でありながら、 現在は priv/repo/seeds.exs と mix run でしか作成できない。 管理者が自分で運用を始められず、実質的に本稼働できない状態にある。

Context（Offices / Accounts / AuditLogs）は認証実装時に作られており、 今回は一覧クエリと管理者向け画面が中心になる。ルーターの :require_admin の live_session も空のまま残っている。

2. 目的

  • 管理者がコンソールを触らずに拠点とアカウントを発行・変更できる状態にする
  • 退職者のアカウントを無効化でき、過去の記録は残る運用を成立させる
  • 初回パスワード設定とパスワード忘れを、管理者がログインリンクの再送で救済できるようにする
  • これまで書きためた監査ログを、管理者が画面で追えるようにする

3. 対象範囲

#優先度要求
R-1P0 拠点の一覧・登録・編集（/management/offices）。拠点コード・名称・郵便番号・住所・電話番号・有効フラグ
R-2P0 拠点の無効化。物理削除は行わず active = false で運用し、無効な拠点は他機能の選択肢に出さない
R-3P0 ユーザーの一覧・登録・編集（/management/users）。氏名・メールアドレス・所属拠点・ロール・有効フラグ
R-4P0 ユーザーの無効化。無効化後はログインできず、過去に登録した日報などの記録は保持される
R-5P0 ログインリンクの発行。初回パスワード設定とパスワード忘れの救済を、管理者が画面から行える
R-6P0 ロック解除。ログイン失敗10回でロックされたアカウントを、管理者が解除できる
R-7P0 ロックアウトの防止。管理者は自分自身のロール変更・無効化ができない
R-8P0 ユーザー操作の監査ログ記録。登録・更新・ロール変更を記録する（PRD セキュリティ「ユーザー権限の変更」）
R-9P0 監査ログ一覧（/management/audit_logs）。操作者・操作日時・対象・変更内容を、リソース種別・操作・操作者で絞り込んで参照できる。管理者のみ
R-10P0 アクセス制御。運行管理者・一般利用者はメニューに表示されず、URL直接指定でもブロックされる
R-11P1 運転者台帳との紐付けの可視化。ユーザー一覧・編集画面で、紐付いた運転者が分かるようにする

4. 対象外（今回やらないこと）

項目理由
管理者によるメールアドレスの変更到達確認ができないため。変更は本人が /users/settings から確認メール経由で行う。登録時のみ入力可とする
管理者による初期パスワードの設定平文のパスワードを管理者が知る運用を作らない。発行はログインリンクに一本化する
拠点・ユーザーの削除参照整合と記録の保持のため、無効化で運用する（PRD データ保持）
拠点の監査ログ記録PRD の監査対象の列挙に拠点マスタが含まれない。加えて初期拠点の作成時には操作者が存在しない
監査ログのCSV出力F-7 のCSV出力でまとめて扱う

5. 受け入れ条件

  • 管理者が画面から拠点とユーザーを登録でき、登録したユーザーにログインリンクが届く
  • 重複する拠点コード・メールアドレスは、フォーム上でエラーになり保存されない
  • 無効化したユーザーはログインできず、そのユーザーが作成した日報は一覧に残る
  • 無効化した拠点は、車両・運転者・ユーザーの拠点選択肢に出ない
  • 管理者は自分自身のロールを変更できず、自分を無効化できない
  • ユーザーのロールを変更すると、監査ログに role_change として記録される
  • 運行管理者が /management/users にURL直接アクセスするとブロックされる
  • 監査ログ一覧で、リソース種別・操作・操作者で絞り込める
  • make check（compile / format / credo / test）がすべて通る
前提：認証（ログイン・マジックリンク・設定画面）、Offices / Accounts / AuditLogs Context、3層の認可（plug・on_mount・クエリ）は実装済み。
