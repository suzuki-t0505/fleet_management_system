.steering / 20260913-operation-reports

設計：運行日報

要求内容は requirements.html。

1. 全体方針

  • エラーと警告を明確に分ける。エラーは changeset（保存不可）、警告は Context が返す別のリストとして扱い、画面で表示する
  • オドメーター逆転の扱いはロールで変える。運転者は保存不可、運行管理者は備考を入力して保存可（V-10）。changeset にオプションで厳格さを渡す
  • 状態遷移は業務上の動詞で表す（coding-rules.md 4.1）。submit_report/2 approve_report/3 reject_report/4 を用意し、update_* に押し込めない
  • 運転者の画面はモバイルを主対象にする。1カラム・大きめの入力欄・段階的な入力（出発 → 帰着 → 給油）
  • 給油記録は日報に従属する子エンティティ。専用 Context を作らない（coding-rules.md 2.1）

5.2 運転者向けフォーム（R-7・最重要）

  • 1カラム。セクションは 運行 → 出発 → 帰着 → 給油 → その他 の順で、実際の業務の順に並べる
  • 車両・運転者は自拠点の選択肢。運転者は current_scope.driver_id を既定選択し、一般利用者は変更できない
  • 運行日は当日を既定値にする
  • オドメーターは inputmode="numeric" とし、走行距離をその場で自動表示する（読み取り専用）
  • 給油は「給油を追加」ボタンで行を増やす（inputs_for + sort_param / drop_param）
  • 保存ボタンは「下書き保存」と「提出」の2つ。提出時のみ確認を挟む
  • 警告はフォーム上部にまとめて表示し、提出を妨げない（運行管理者の場合）

5.3 運転者向け一覧・詳細

  • 一覧は自分の日報のみ。ステータスバッジ付きのカード表示を主とする（モバイル前提）
  • 差戻しの日報を最上部に固定表示し、理由を明示する
  • 詳細は読み取り専用。下書き・差戻しのときのみ「編集」ボタンを表示する

5.4 運行管理者向け一覧・詳細

  • 一覧：期間（既定は当月）・車両・運転者・ステータスで絞り込み。「未承認のみ」への切り替えを1クリックでできるようにする
  • 列：運行日 / 車両 / 運転者 / 走行距離 / 出発〜帰着 / ステータス
  • 詳細：日報の全項目 + 給油記録 + 警告（オドメーターの逆転など）を表示
  • 提出済みのときのみ「承認」「差戻し」ボタンを表示。差戻しは理由の入力欄を開いてから実行する

8. テスト方針

対象内容
スコープ境界一般利用者は他人の日報を取得・一覧できない。運行管理者は他拠点を見られない。運転者未紐付けの利用者は0件
changeset（エラー）V-9・V-14・V-15・V-16・追加1・追加2 と必須項目
V-10 のロール差同じ入力で、運転者は {:error, _}、運行管理者は {:ok, _} になること
警告前回オドメーターとの逆転・同一時間帯の重複で警告が返る。保存自体は成功する
走行距離保存時に算出される。パラメータで distance_km を渡しても無視される
給油記録日報と同時に保存される。給油量が0のとき日報ごと保存されない（V-17のロールバック）
状態遷移下書き→提出→承認／差戻し→再提出。各ロールで許可される遷移のみ実行できる
承認車両の latest_odometer が更新される。より小さい値では更新されない。監査ログが残る
差戻し理由が無いと失敗する。差戻し後は運転者が編集できる
LiveView作成→提出→承認の一連、差戻し→再提出、編集不可のときボタンが出ないこと

9. リスクと対応

リスク対応
ロールによって検証の強さが変わる設計が複雑になる切り替えは strict: オプション1つに限定し、判断は Context（create/update）で行う。スキーマ側はオプションを受け取るだけにする
inputs_for による給油記録の動的追加・削除Phoenix 1.8 の sort_param / drop_param を使う。噛み合わない場合はJSなしの「行を追加」ボタン（サーバ側で空要素を足す）に切り替える
日跨ぎ運行での運行日の扱い運行日は出発日の日付と同日または翌日までを許容し、ユーザーが選べるようにする。既定は出発日
承認時の車両更新で競合が起きる同一トランザクション内で車両を取得し直して比較する
モバイルでの入力量が多く離脱する下書き保存を用意する。必須項目を7つに絞り、任意項目は折りたたむ
