要求内容：プロジェクト初期整備

機能実装に着手する前に、テンプレート由来の不整合を解消し、永続ドキュメントで決めた技術方針をリポジトリに反映する。

1. 背景

本リポジトリは phx.new 由来のスケルトン（CoreApp）のままで、ドメインコードが存在しない。 永続ドキュメント6点（product-requirements.md / functional-design.md / architecture.md / repository-structure.md / glossary.md / development-guidelines.md）を整備した結果、 ドキュメントで決めた方針とリポジトリの実体に9件の乖離があることが判明した。

この状態では make check が通らず（credo 未導入）、品質ゲートを機能させられない。 機能実装の前に解消する。

2. 目的

  • make check が成功する状態にし、以降のすべての作業で品質ゲートを機能させる
  • architecture.md で選定した依存（Oban / 認証 / GCS / CSV）を導入し、機能実装をすぐ始められる状態にする
  • テンプレート由来の誤り（unifield 残骸・スペル誤り・非推奨記法）を除去する
  • DESIGN-notion.md のデザイントークンを Tailwind に定義し、UI実装の土台を作る

3. 対象範囲

#優先度要求対象ファイル
R-1P0credo を導入し make mix_credo / make check を通すmix.exs / .credo.exs
R-2P0技術仕様書で選定した依存を追加する（oban / bcrypt_elixir / goth / google_api_storage / nimble_csv）mix.exs / config/*.exs
R-3P0Oban を起動し、キュー構成と cron の枠を用意する（ジョブ本体は本作業の対象外）application.ex / config/*.exs / priv/repo/migrations
R-4P0mix phx.gen.auth で認証基盤を作り、Accounts.Scope を本システムの要件（拠点・ロール）に拡張するlib/core_app/accounts* / lib/core_app_web/user_auth.ex / router.ex
R-5P0DESIGN-notion.md のトークン（colors / typography / rounded / spacing）を Tailwind の @theme に定義するassets/css/app.css
R-6P0Layouts.app を実装する（サイドバー・ヘッダー・フラッシュ表示）components/layouts.ex / layouts/app.html.heex
R-7P1docker-compose.yml のノード名・Cookie を unifield から core_app に変更し、非推奨の version: '3' を削除するdocker-compose.yml
R-8P1test/fleet_managment_system_web/ を test/core_app_web/ にリネームするtest/
R-9P1.gitignore の fleet_managment_system-*.tar を修正し、.env・サービスアカウントキーの除外を追加する.gitignore
R-10P1CLAUDE.md の技術スタック記載を実体（Elixir 1.20.4 / Phoenix 1.8.13）に合わせるCLAUDE.md

4. 対象外

  • 業務機能の実装（車両台帳・運転者台帳・運行日報・点検整備・事故ヒヤリ）— 次回以降の作業
  • Oban ジョブの本体実装（期限アラートの判定・メール送信）— 起動とキュー構成の枠のみ
  • GCS 連携の実装（Utils.Gcs）— 依存の追加のみ。実装は添付ファイル機能と同時に行う
  • 本番用 Dockerfile と CI（GitHub Actions）の作成— デプロイ準備時に別作業とする
  • GCP インフラの構築（Cloud Run / Cloud SQL / GCS のプロビジョニング）
  • OTPアプリ名のリネーム— core_app のまま使うと決定済み（architecture.md 8.3）

5. 完了条件

#条件
C-1make check（compile / format / credo / test）がすべて成功する
C-2ログイン画面が表示され、seeds で投入した管理者アカウントでログインできる
C-3ログイン後の画面が Layouts.app で表示され、DESIGN-notion のトークン（背景 canvas-soft、主要ボタン primary）が適用されている
C-4ロール（admin / manager / member）と拠点を持つユーザーが作成でき、Accounts.Scope から参照できる
C-5Oban が起動し、LiveDashboard またはログでキューの待機が確認できる
C-6リポジトリ内に unifield / fleet_managment（スペル誤り）の文字列が残っていない
C-7CLAUDE.md と architecture.md のバージョン記載が一致している

6. 前提・制約

  • すべてのコマンドは Docker コンテナ上で実行する（development-guidelines.md 2.2）
  • コードの書き方は coding-rules.md、UIの見た目は DESIGN-notion.md に従う
  • GCP のサービスアカウントキーは未入手のため、goth は依存追加と設定の雛形までとする
  • メール配信サービス（SendGrid 等）は未契約のため、開発環境の Swoosh.Adapters.Local のままとする
