2. データモデル

2.1 shippers（荷主）

カラム型備考
office_idULID FK必須。on_delete: :restrict
namestring(255)必須。拠点内で一意（[:office_id, :name] ユニーク）
codestring(50)任意
notetext任意
statusEcto.Enumactive（既定）/ inactive。物理削除はしない

2.2 dispatches（配車）

カラム型備考
office_idULID FK車両の拠点に従う（非adminは scope の拠点を強制）
shipper_idULID FK必須。同一拠点の有効な荷主のみ
vehicle_id / driver_idULID FK必須。同一拠点のものに限る
created_by_user_idULID FK登録者
titlestring(255)必須
descriptiontext任意
started_at / ended_atutc_datetime必須。ended_at > started_at
pricing_typeEcto.Enumcourse_total（コース一括）/ per_delivery（配送ごと）
course_fare_yenintegercourse_total のとき必須（0以上）。per_delivery のときは nil
toll_yeninteger既定0、0以上

インデックス: [:office_id, :started_at] / [:vehicle_id, :started_at] / [:driver_id, :started_at] / [:shipper_id]

2.3 dispatch_deliveries（配送明細）

カラム型備考
dispatch_idULID FK必須。親削除は cast_assoc の on_replace: :delete で行う
positioninteger表示順（フォームの並び順で採番）
destinationstring(255)必須（自由入力）
fare_yenintegerper_delivery のとき必須（0以上）。course_total のときは nil に正規化
per_delivery は明細1件以上が必須。course_total は明細0件でもよい（配送先を残したい場合のみ入力）。

3. 業務ルール

IDルール
D-1終了日時は開始日時より後
D-2受取金額 total_amount_yen：course_total = course_fare_yen + toll_yen、per_delivery = Σ fare_yen + toll_yen。純関数として Dispatch に置き、テンプレートでは計算しない
D-3料金方式を切り替えて保存したとき、使わない側の金額（course_fare_yen または各 fare_yen）は nil に正規化する
D-4時間重複の警告（非ブロッキング）：自分以外の配車で、同一車両または同一ドライバーの [started_at, ended_at) が重なる場合。OperationReports.warnings/2 と同じ形で返す
D-5荷主・車両・ドライバーは scope の拠点内から選ぶ。拠点外の ID を指定した場合は changeset エラー
D-6無効な荷主は新規・編集の選択肢に出ない（編集時、既に紐付いている無効荷主は選択肢に残す）

5.1 配車フォーム

  • 料金方式のラジオ（コース一括 / 配送ごと）で入力欄を切り替える。phx-change で validate を呼び、サーバー側の changeset 値で表示を決める
  • コース一括：コース料金の入力欄 + 配送先（任意・複数）
  • 配送ごと：配送明細の行（配送先 + 配送料金）を追加・削除。inputs_for と sort_param / drop_param を使う
  • 高速料金は常に表示。画面下部に合計金額をプレビュー表示（changeset から D-2 で計算）
  • 重複警告は maintenance_live の警告ボックスと同じ配置
デザイン：配送明細の「行の追加・削除」ボタンは DESIGN-notion.md に定義が無い。button-secondary / button-icon-circular の組み合わせで実装し、実装時に DESIGN-notion.md へ追記する。

6. 認可

  • 3層で守る：:require_manager_user plug → on_mount :require_manager → Context の scoped/2
  • member 向け /dispatches は Context 側で driver_id == scope.driver_id を必須にする。他人の配車は get_dispatch! が not found
  • ボタンの :if 非表示は認可として扱わない

7. CSV出力・集計

  • Exports：配車1行 = 1レコード。配送先は 、 区切りで1セルに連結、配送料金は合計と方式を別列で出力
  • 列：配送開始・配送終了・タイトル・説明・荷主・方式・コース料金・配送料金合計・高速料金・受取金額合計・車両・ドライバー・配送先
  • 集計は期間（月）と軸を既存 Reports の期間指定に合わせる。日報と異なり承認の概念が無いため、全配車を対象とする。月は started_at のJST基準
