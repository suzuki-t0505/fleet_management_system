要求内容：配車管理

対象機能: F-10 車両の予約・配車管理（product-requirements.md F-10 / glossary.md 12）。Issue #7

1. 背景

運行日報（F-3）は「走った結果」を記録するもので、「誰がどの車両でどの荷主のどの配送を、いくらで請け負うか」を登録する場所が無い。 配送の予定・実績と受取金額が紙や表計算に分散している。

受取金額は コース一括（コースでトータルいくら） と 配送ごと（1配送いくら） の2方式があり、 1件の配車ごとにどちらかを選べる必要がある。

2. 目的

  • 配送の開始・終了時間、タイトル、説明、荷主、配送先、配送料金、高速料金、車両、ドライバーを登録・閲覧できるようにする
  • コース一括・配送ごとの2方式の受取金額を、1つの画面・1つの合計で扱えるようにする
  • 同じ車両・ドライバーの時間重複に登録時に気付けるようにする
  • 荷主・車両・ドライバー別の売上を集計し、CSVで出力できるようにする

3. 対象範囲

#優先度要求
R-1P1 荷主マスタ。拠点ごとに荷主（名称・コード・備考・有効/無効）を登録・編集・閲覧できる。物理削除はせず無効化で運用する
R-2P1 配車の登録・編集。配送開始時間・配送終了時間・タイトル・説明・荷主・車両・ドライバー・高速料金を入力できる。終了は開始より後
R-3P1 料金方式の選択。コース一括はコース料金（総額）を1つ入力、配送ごとは配送明細（配送先 + 配送料金）を複数行入力する
R-4P1 配送先は自由入力。コース一括でも配送先を複数登録できる（料金は持たない）
R-5P1 受取金額の合計。コース一括 = コース料金 + 高速料金、配送ごと = 配送料金の合計 + 高速料金。一覧・詳細に表示する
R-6P1 配車一覧。期間・荷主・車両・ドライバー・キーワードで絞り込み、ページングできる
R-7P1 配車詳細。配送明細・料金内訳・合計を表示する
R-8P1 時間重複の警告。同一車両・同一ドライバーの時間が他の配車と重なる場合、保存はできるが警告を表示する
R-9P1 権限。管理者は全拠点、運行管理者は自拠点の登録・編集・閲覧。一般利用者（ドライバー）は自分に割り当てられた配車の閲覧のみ
R-10P1 監査ログ。荷主・配車の作成・更新を同一トランザクションで記録する
R-11P1 売上集計レポート。月 × 荷主 / 車両 / ドライバーの売上（運賃 + 高速料金）。集計レポートのCSV出力に対応
R-12P1 配車一覧のCSV出力。画面の絞り込み条件を反映、既存のCSV形式（UTF-8 BOM・CRLF・日本語ヘッダー・上限50,000件）に従う

4. 対象外（今回やらないこと）

項目理由
車両の予約申請・承認フローF-10 の後半。今回は管理者が直接配車を登録する
カレンダー・ガントチャート表示DESIGN-notion.md に定義が無く、先に定義が必要。一覧で代替する
配送先のマスタ化自由入力で開始する。必要になった段階でマスタ化する
配車と運行日報の紐付け運用が固まってから別タスクで検討する
配車ステータス（予定・完了など）今回は要求に無い。時刻のみで予定/実績を表す
請求書・配送伝票の発行、荷主向け公開PRDで対象外
ドライバーによる配車の編集閲覧のみとする

5. 受け入れ条件

  • 荷主を登録・編集・無効化でき、無効な荷主は配車の選択肢に出ない
  • コース一括の配車は、コース料金と高速料金の合計が一覧・詳細に出る
  • 配送ごとの配車は、複数の配送明細の料金合計に高速料金を足した額が出る
  • 料金方式に応じた必須入力が検証される（コース一括=コース料金、配送ごと=各明細の配送料金）
  • 終了時間が開始時間以前だとエラーになる
  • 同じ車両またはドライバーの時間重複で警告が出て、保存は可能
  • 運行管理者は他拠点の荷主・配車を参照・指定できない（存在しない場合と同じ応答）
  • ドライバーは自分の配車だけが一覧に出て、編集・作成の URL は拒否される
  • 売上集計が月別・軸別に出て、CSVに出力できる。配車一覧のCSVに絞り込みが反映される
  • make check（compile / format / credo / test）がすべて通る
前提：高速料金は受取額に含める（合計 = 運賃 + 高速料金）。実費コストとして扱う場合は R-5・R-11 を変更する。 時刻はUTC保存・JST表示、金額は整数円。F-1〜F-7 は実装済み。
