要求内容：事故・ヒヤリ記録と改善報告

対象機能: F-6 事故・ヒヤリ記録と改善報告（product-requirements.md F-6 / functional-design.md 4.3・5.2・6.5）＋添付ファイル基盤（architecture.md 4.4）

1. 背景

最後に残ったP0機能。事故・ヒヤリは紙の報告書で提出され、原因分析と改善策が個人のファイルに留まるため、 同じ事故が別の拠点で繰り返される。ヒヤリハットは「報告しても何も起きない」ため、そもそも報告されない。

記録から改善報告の承認までを1本の流れにし、全社共有されたヒヤリを全員が読める状態にすることで、 「報告が横展開につながる」実感を作る。

あわせて、これまで各機能で先送りしてきた添付ファイル（現場写真・修理見積）をここで実装する。 事故記録は写真が付かないと状況が伝わらないため、この機能と同時に必要になる。

2. 目的

  • 全ロールがその場（スマートフォン）から事故・ヒヤリを報告できる状態にする
  • 報告 → 原因分析 → 改善策 → 承認 の進捗が、記録を見れば分かる状態にする
  • 全社共有されたヒヤリを、他拠点の運転者も読めるようにする（個人が特定されない形で）
  • 車両の不具合報告を、運行管理者が取りこぼさない状態にする
  • 添付ファイルの保存・参照の基盤を作り、車両・点検整備でも使えるようにする

3. 対象範囲

#優先度要求
R-1P0 事故・ヒヤリの報告（全ロール）。発生日時・区分・車両・運転者・場所・天候・発生状況を記録する
R-2P0 区分の使い分け。人身 / 物損 / 車両単独・不具合 / ヒヤリハットの4区分
R-3P0 原因分析と改善策の登録（運行管理者）。直接原因・背景要因・対策内容・実施予定日・実施責任者
R-4P0 状態遷移（報告 → 分析中 → 改善策登録済み → 完了）と差戻し。改善策の登録には直接原因と対策内容が必須（V-25）
R-5P0 承認は報告者本人以外が行う（V-26）。自分の報告を自分で承認できない
R-6P0 全社共有（管理者のみ設定）。共有された記録は全拠点の全ロールが参照できる
R-7P0 他拠点から見るときの匿名化（V-27）。運転者氏名・報告者氏名を伏せる
R-8P0 添付ファイル（V-28）。PDF / JPEG / PNG、1ファイル10MB、1記録10ファイルまで。保存先を差し替えられる形にし、開発・テストはローカル保存、本番は GCS を使う
R-9P0 添付の参照制御。公開URLを持たせず、参照権限のある利用者だけがダウンロードできる
R-10P0 一般利用者向け画面（/incidents）。自分の報告と全社共有された記録を参照し、375pxで報告を完了できる
R-11P0 運行管理者向け画面（/management/incidents）。区分・ステータス・期間・拠点で絞り込み、詳細から分析・承認を行う
R-12P0 ダッシュボード連携。運行管理者に「未対応の車両不具合報告」「改善報告が未完了」の件数、一般利用者に「全社共有された新着ヒヤリ3件」
R-13P1 車両詳細からの導線。車両ごとの事故・ヒヤリ履歴を表示する

4. 対象外（今回やらないこと）

項目理由
GCS アダプタの動作確認開発環境にサービスアカウントの認証情報が無いため実行できない。実装は入れるが未検証であることを明記する
車両・点検整備への添付の組み込み基盤（Context・ストレージ・コンポーネント）は汎用に作るが、画面への組み込みは事故・ヒヤリのみ。車両（V-5）は別作業
事故・ヒヤリの集計F-7 の範囲。本作業ではデータの蓄積までを行う
記録の削除他の台帳と同じく物理削除は行わない。10年保持（PRD データ保持）
報告時のメール通知MVP の送信種別に含まれない（architecture.md 4.5）

5. 受け入れ条件

  • 一般利用者が事故・ヒヤリを報告でき、一覧に自分の報告が出る
  • 他人の報告（全社共有されていないもの）は一般利用者の一覧に出ない
  • 発生日時に未来日時を入れると保存できない
  • 直接原因または対策内容が空のまま「改善策を登録」に進めない
  • 報告者本人には承認ボタンが表示されず、Context でも拒否される
  • 全社共有された記録を他拠点の利用者が開くと、運転者氏名・報告者氏名が伏せられる
  • 10ファイルを超える添付、10MBを超えるファイル、PDF/JPEG/PNG 以外は受け付けない
  • 拡張子を偽装したファイル（先頭バイトが一致しない）は受け付けない
  • 権限の無い利用者が添付のURLを直接叩くとブロックされる
  • make check（compile / format / credo / test）がすべて通る
前提：車両台帳・運転者台帳・運行日報・点検整備・拠点/ユーザー管理は実装済み。 goth と google_api_storage は依存に入っているが未使用。
