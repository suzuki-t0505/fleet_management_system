2. 荷積み・荷降ろし時刻

2.1 データモデル

カラム（dispatch_deliveries）型備考
loading_atutc_datetime荷積み日時。任意（NULL可）
unloading_atutc_datetime荷降ろし日時。任意（NULL可）

既存行は両方NULLのまま残る（データ移行なし）。カラム追加のみで、def change で戻せる。

2.2 業務ルール

IDルール
B-1荷積み・荷降ろしは任意。片方だけの入力も可
B-2両方入力された場合、unloading_at > loading_at
B-3入力された時刻は、親の配車の started_at 以上 ended_at 以下（境界を含む）
B-4料金方式（コース一括/配送ごと）に関わらず入力できる。D-3 の正規化（fare_yen を nil にする）の対象にしない

B-3 は親の日時が必要なため、Dispatch.changeset/2 が cast_assoc の with: で Delivery.changeset(delivery, attrs, index, pricing_type, started_at, ended_at) に渡す（料金方式を渡している既存の仕組みと同じ）。 親の日時が未入力・不正のときは B-3 を検証しない（親側のエラーが先に出るため）。

2.3 入出力

  • フォーム：配送先の行に datetime-local を2つ追加（荷積み日時・荷降ろし日時）。JST入力 → UTC保存（ConvertDatetime.parse_input/1）。 Dispatches.defaults/3 に、明細の loading_at / unloading_at の変換を追加する（運行日報の給油の変換と同じ）
  • 詳細：配送先の表に「荷積み」「荷降ろし」列を追加（format_datetime/1、未入力は -）。運転者向けにも表示する（料金ではないため）
  • CSV：「荷積み時刻」「荷降ろし時刻」の2列を末尾に追加。配送先と同じ順に 、 区切りで連結し、未入力は -。 DBで string_agg（JST変換・MM/DD HH24:MI）して1行1配車を保つ
  • 監査ログ：既存の changes に明細の変更として含まれる（変更不要）

3. 配車表

3.1 画面とURL

URL権限内容
/management/dispatches/boardmanager以上配車表。クエリ date（YYYY-MM-DD、既定=今日JST）、axis（vehicle 既定 / driver）、office_id（管理者のみ）
/dispatches/boardログイン済み運転者向け。自分の配車だけ。date のみ（行は自分1行）

/:id より前に定義する（board を ID と解釈させない）。サイドナビに「配車表」を追加し、配車一覧の操作に「配車表」リンクを追加する。

3.2 取得（Context）

Dispatches.list_dispatches_for_day(scope, date, params)：[その日0:00 JST, 翌日0:00 JST) と時間が重なる配車を返す （started_at < 翌日0:00 and ended_at > その日0:00）。スコープは既存の scoped/2 を使い、拠点・他人の配車は入らない。 荷主・車両・ドライバー・明細を preload。ページングはしない（1日分のため。上限なし）。

行（縦軸）は、車両なら Vehicles.all_selectable_vehicles/1、ドライバーなら Drivers.all_selectable_drivers/1 を使い、 配車の無い行も表示して空きが分かるようにする。その日に配車がある行は、廃車・退職で選択肢に無くても追加する。 一般利用者は、自分の配車の車両の行だけを出す。

3.3 配置計算（Dispatches.Board、純関数）

関数内容
build(dispatches, rows, date, axis)行ごとのバー一覧を返す。%{row, lanes, bars: [...]}
バーの位置JSTのその日の0:00を基準に、left = 開始までの秒数 / 86400、width = 長さ / 86400（%）。その日の範囲に切り詰める（R-8）。切った側は continues_from_prev / continues_to_next を立てる
重なりの配置（レーン）開始時刻順に、置ける最も上のレーンに割り当てる（貪欲法）。同じ行で時間が重なるとレーンが2以上になり、overlap: true を立てる。終了=開始は重ならない（V-32と同じ）
印（マーカー）明細の loading_at / unloading_at のうちその日の範囲内のものを、バー内の位置（%）と種別（積/降）で返す
荷主の色荷主IDのリストを並べ、色パレットを順番に割り当てる（同じ荷主は同じ色）。パレットは DESIGN-notion.md の既存アクセント色のトークンを使う

日付はすべてJST。ConvertDatetime でUTCとの変換を行い、Date.utc_today は使わない。

3.4 描画（BoardComponents）

  • 横軸：0〜24時。1時間ごとの縦の罫線と時刻ラベル（0, 2, 4, …）。今日の場合は現在時刻の縦線を出す
  • 縦軸：行名（車両番号 / ドライバー名）を左の固定列に出す。行の高さは レーン数 × バーの高さ
  • バー：絶対配置（left / width を % で指定）の <.link navigate>。タイトル・荷主・時間帯を表示し、幅が狭いときは省略表示（truncate）。title 属性で全文を出す
  • 印：バー内に小さな縦線を重ね、積（▲）・降（▼）の別が分かる。ホバーで配送先と時刻を出す
  • 重なり：バーの縁をオレンジの警告色にする。続きがある側は端を角にして「←」「→」を付ける
  • 凡例：荷主の色、重なり、続きの意味を表の下に出す。配車が無い日は空状態のメッセージ
  • スマートフォン：表の最小幅（例 960px）を確保して横スクロール。行名の列は固定（sticky）
  • JSライブラリは使わない。phx-change の日付・軸の切替と push_patch のみ（一覧画面と同じ方式）
デザイン：DESIGN-notion.md にタイムラインの定義が無い。実装前に「配車表（timeline）」として、 行の高さ・バーの高さと角丸・色の割当・罫線・警告色・現在時刻線のトークンを追記し、その定義に従う。

3.5 操作

  • 前日 / 今日 / 翌日のリンクと日付入力（push_patch で ?date= を更新）。不正な日付は今日にする
  • 縦軸の切替（車両/ドライバー）、管理者は拠点の絞り込み
  • 「配車を登録」へのリンク（日付を初期値として渡すことはしない。今回は既存の新規登録へ遷移のみ）

5. テスト方針

対象観点
Delivery / Dispatches（時刻）B-1〜B-4：任意入力、荷降ろし≦荷積みでエラー、範囲外でエラー（境界は許可）、親の日時が未入力なら検証しない、JST入力がUTCで保存される、更新で消せる、既存の料金方式の切替が壊れない
CSV荷積み・荷降ろし列が配送先と同じ順で連結される。未入力は -。他拠点が混ざらない（既存テストが通る）
Dispatches.Board（純関数）left/width の計算、日付をまたぐ配車の切り詰めと続きフラグ、重なりのレーン割当、終了=開始は重ならない、印の位置、荷主の色が安定、0件の行
list_dispatches_for_dayその日と重なる配車だけ（前日から続く・翌日へ続くを含む、境界ちょうどは含まない）、JSTの日付で切る、他拠点・member の他人の配車を返さない
LiveView（manager）配車がバーとして表示されリンク先が詳細、日付の前後・直接指定、軸の切替（ドライバー）、配車の無い行も出る、重なりの強調、他拠点が出ない、荷積み・荷降ろしの入力と詳細表示
LiveView（member）自分の配車だけ表示、/management/dispatches/board は拒否
